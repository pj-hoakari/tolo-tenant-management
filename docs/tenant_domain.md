# テナントコンテキスト

## 責務

- 顧客組織（テナント）と配下イベントの管理
- テナント／イベント識別子の正本（マスタ）とライフサイクル所有
- ロール種別とオンボーディングの定義
- 所属の読み書きは関係参照が所有（本コンテキストは識別子マスタとして参照される）

## ドメインモデル

| 語 | 英語 | 内容 |
|---|---|---|
| テナント | Tenant | 契約・課金・オンボーディングの単位＝顧客組織<br>改善データの保護境界<br>1ユーザーは複数テナントに所属しうる |
| テナント所有状態 | Tenant Ownership State | `pending_owner`＝未認証で仮作成され、オーナー未確定<br>`owned`＝認証済みユーザーがオーナーとして所属し、利用可能 |
| イベント | Event | テナント配下の催事／設置<br>必ず1テナントに属す<br>グラフ・観測・最適化・行列誘導はイベント単位 |
| イベント種別 | Event Type | 短期（履歴短い・観測縮退対象）／長期（常設） |
| イベント状態 | Event Status | draft→open→locked→closed→archived<br>逆遷移も許容 |
| アーカイブ | Archive | 削除＝論理削除<br>識別子と配下データを保持 |
| ロール | Role | オーナー／スタッフ／管理者（予約）<br>テナントとイベントで独立 |

## ドメインイベント

| イベント | 英語 | 契機 |
|---|---|---|
| テナント登録された | TenantRegistered | オンボーディング完了 |
| テナント契約変更された | TenantContractChanged | プラン変更 |
| イベント作成された | EventCreated | 配下にイベント新設 |
| イベント種別設定された | EventTypeAssigned | 短期／長期設定 |
| イベント公開された | EventOpened | draft→open |
| イベントロックされた | EventLocked | open→locked |
| イベント終了された | EventClosed | locked→closed |
| イベントロック解除された | EventUnlocked | locked→open |
| イベント再開された | EventReopened | closed→open |
| イベントアーカイブされた | EventArchived | 論理削除 |
| イベントアーカイブ復元された | EventUnarchived | archived→closed |
| テナントアーカイブされた | TenantArchived | テナント論理削除 |

所属（メンバーシップ）の書き込みイベントは関係参照が所有

## 不変条件

- 1イベントは必ず1テナントに属す
- 1ユーザーは複数テナントに所属しうる（セルフサインアップ直後はテナント未所属）
- 未認証で作成したテナントは `pending_owner` とし、オーナー確定まで業務利用できない
- 所有権取得は一回限りの取得トークンと認証済みユーザーを必要とし、オーナー所属作成と `owned` への遷移を同一トランザクションで確定する
- `TenantRegistered` は所有権取得の完了時に成立し、`pending_owner` の作成時には成立しない
- 期限切れの `pending_owner` は未登録の仮データとして物理削除できる
- 識別子はテナントが発番する正本（他は参照のみ）
- 状態は前進（draft→…→archived）を基本に逆遷移も許容
- 操作可否は各サービスが参照判断（Edge Bridge Service を除き、各サービスは Service Gateway 発行の内部 JWT を検証する側で、IdP の Resource Server ではない）
- `owned` の削除はソフト削除（アーカイブ）で物理削除せず宙づり参照を生まない
- アーカイブ中は書き込み禁止・参照継続・所属保持
- テナントのアーカイブは配下イベントの状態を変えない
- 許容する状態遷移はドメインイベントを伴う経路に限る（同一状態への遷移と、イベントの定義にない逆遷移は許容しない）
- draft のイベントはアーカイブによって破棄できる。アーカイブからの復元先は closed で、draft へは戻らない
